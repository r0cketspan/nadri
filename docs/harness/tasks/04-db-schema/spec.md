## 1. 작업 목표

ERD 19개 테이블 중 01에서 만들지 않은 **15개**를 테이블 생성 스크립트(Alembic 리비전) 하나로 만들고, 같은 모양의 ORM 모델과 "DB 설명(COMMENT) = ERD" 대조 테스트를 만든다 [PL §3].

- 끝나면: `alembic upgrade head`로 19개 테이블이 생기고, 모든 테이블·컬럼 COMMENT가 ERD 한글 명칭과 같으며, 외래키 삭제 동작(연쇄 삭제·NULL로 비우기)이 [A] §5.1대로 동작하고, `nadri_tools` 롤은 새 테이블에 아무 권한이 없다.
- 추적: [A] §5.1 · FR-104(90일 연쇄 삭제의 바탕) · NFR-33·35(원문·좌표 컬럼 없음) · NFR-07(최소 권한).

## 3. 설계 규칙 (15개 테이블 공통)

1. **한글 COMMENT = ERD**: 테이블 COMMENT = `T[테이블][1]`, 컬럼 COMMENT = 그 컬럼 행의 4번째 값. **각주 표시(①~⑤)와 그 앞 공백은 뺀다**(예: `"가입 상태 ①"` → `"가입 상태"`, `"FAQ 캐시 ID ⑤"` → `"FAQ 캐시 ID"`). 괄호 설명은 그대로 둔다(예: `"내용 (가린 텍스트)"`, `"비용(USD)"`). 정규화 함수는 테스트와 같은 규칙: `re.sub(r"\s*[①-⑳]", "", s).strip()` (확인 질문 Q2).
2. 모든 시각은 `timestamptz`, "하루"는 KST 날짜(`date`) [A §5.1].
3. 정수 ID는 `bigint GENERATED BY DEFAULT AS IDENTITY`(SQLAlchemy `sa.Identity()`). `chat_sessions.id`만 `uuid`(기본값 `gen_random_uuid()` — PostgreSQL 13+ 내장).
4. **열거형 텍스트 컬럼은 CHECK 제약**으로 허용값을 막는다. 허용값은 ORM 모듈의 상수(튜플)가 정본이고, 테이블 생성 스크립트는 그 값을 **복사**해 적는다(테이블 생성 스크립트는 나중에 ORM이 바뀌어도 변하지 않아야 하므로 ORM을 import하지 않는다). 둘이 같은지는 테스트로 확인한다(test.md D-CHK).
5. **제약 이름은 명시**한다(오류 처리·되돌리기에서 이름으로 찾음). 규칙: `pk_<테이블>`, `fk_<테이블>_<컬럼>`, `uq_<테이블>_<컬럼들>`, `ck_<테이블>_<컬럼>`, `ix_<테이블>_<컬럼들>`. 05는 `uq_users_username`·`uq_users_email` 이름으로 중복 가입을 구분한다.
6. 원문 입력·위치 좌표를 담는 컬럼은 만들지 않는다(NFR-33·35). `chat_messages.content`(user)는 가린 텍스트만 들어간다는 것을 COMMENT("내용 (가린 텍스트)")로도 드러낸다.
7. 롤: 테이블 소유자는 `nadri_app`(ingest가 테이블 생성 스크립트를 이 롤로 실행 — 01 Q1). `0002`는 **GRANT를 하나도 하지 않는다** → `nadri_tools`는 새 테이블에 권한 없음(01 Q2에서 기본 권한(`ALTER DEFAULT PRIVILEGES`)을 쓰지 않기로 했으므로 자동 부여도 없음).

## 4. 테이블 정의 (정본)

표기: `NN` = NOT NULL, 기본값은 DB `server_default`. FK 동작은 `ON DELETE`만 적는다(UPDATE는 기본값). COMMENT 열은 ERD에서 각주를 뺀 값.

### 4.1 `account.py`

**허용값 상수**
```python
USER_ROLES: tuple[str, ...] = ("user", "admin")
USER_STATUSES: tuple[str, ...] = ("pending", "active", "rejected", "disabled")
```

**`users` — ORM `User` — COMMENT '사용자'**
| 컬럼 | 타입 | 제약·기본값 | COMMENT |
|---|---|---|---|
| id | bigint | PK `pk_users`, identity | 사용자 ID |
| username | text | NN, UNIQUE `uq_users_username` | 아이디 |
| email | text | NN, UNIQUE `uq_users_email` | 이메일 |
| password_hash | text | NN | 비밀번호 해시 |
| role | text | NN, 기본 `'user'`, CHECK `ck_users_role` ∈ USER_ROLES | 권한 |
| status | text | NN, 기본 `'pending'`, CHECK `ck_users_status` ∈ USER_STATUSES | 가입 상태 |
| created_at | timestamptz | NN, 기본 `now()` | 가입 신청 일시 |
| approved_at | timestamptz | NULL | 승인 일시 |
| approved_by | bigint | NULL, FK `fk_users_approved_by` → users.id **SET NULL** | 승인 관리자 |

- `username`·`email`은 **앱이 정규화(소문자 등)한 값**을 저장한다(규칙은 05 spec). DB는 대소문자 구분 없는 유일성을 따로 강제하지 않는다(정규화가 단일 진입점).

**`auth_sessions` — ORM `AuthSession` — COMMENT '로그인 세션'**
| 컬럼 | 타입 | 제약·기본값 | COMMENT |
|---|---|---|---|
| id_hash | text | PK `pk_auth_sessions` | 세션 키 해시 |
| user_id | bigint | NN, FK `fk_auth_sessions_user_id` → users.id **CASCADE**, 인덱스 `ix_auth_sessions_user_id` | 사용자 ID |
| created_at | timestamptz | NN, 기본 `now()` | 로그인 일시 |
| last_seen_at | timestamptz | NN, 기본 `now()` | 마지막 활동 일시 |
| expires_at | timestamptz | NN | 만료 일시 |

- `ix_auth_sessions_user_id`: 비밀번호 변경·재설정·비활성화 때 "그 사용자의 세션 전부 삭제"에 쓴다(05·06·18).

**`password_reset_codes` — ORM `PasswordResetCode` — COMMENT '비밀번호 재설정 코드'**
| 컬럼 | 타입 | 제약·기본값 | COMMENT |
|---|---|---|---|
| id | bigint | PK `pk_password_reset_codes`, identity | 코드 ID |
| user_id | bigint | NN, FK `fk_password_reset_codes_user_id` → users.id **CASCADE**, 인덱스 `ix_password_reset_codes_user_id` | 사용자 ID |
| code_hash | text | NN | 인증코드 해시 |
| expires_at | timestamptz | NN | 만료 일시 |
| attempts | int | NN, 기본 `0`, CHECK `ck_password_reset_codes_attempts` `attempts >= 0` | 시도 횟수 |
| consumed_at | timestamptz | NULL | 사용 일시 |

**`rate_limits` — ORM `RateLimit` — COMMENT '요청 제한'**
| 컬럼 | 타입 | 제약·기본값 | COMMENT |
|---|---|---|---|
| key | text | PK `pk_rate_limits` (예: `login:ip:1.2.3.4` — 키 형식은 05 spec) | 제한 키 |
| window_start | timestamptz | NN | 집계 시작 일시 |
| count | int | NN, 기본 `0`, CHECK `ck_rate_limits_count` `count >= 0` | 횟수 |
| locked_until | timestamptz | NULL | 잠금 해제 일시 |

## 5. 테이블 생성 스크립트 `0002_app_tables.py`

```python
revision = "0002"
down_revision = "0001"   # 01이 정한 0001 리비전 ID와 같게 (01 spec은 파일명만 정함 — 구현 시 01 파일의 revision 값을 따른다)

def upgrade() -> None:
    """앱 테이블 15개를 만든다(한글 COMMENT·제약 포함). 권한은 부여하지 않는다."""
def downgrade() -> None:
    """upgrade의 역순으로 15개 테이블을 지운다. 01 테이블 4개는 건드리지 않는다."""
```
`upgrade()` 처리 순서:
1. `users` → `auth_sessions` → `password_reset_codes` → `rate_limits`
2. `chat_sessions` → `chat_messages`(faq_cache_id 컬럼은 만들되 FK는 아직 없음) → `faq_cache` → `op.create_foreign_key("fk_chat_messages_faq_cache_id", "chat_messages", "faq_cache", ["faq_cache_id"], ["id"], ondelete="SET NULL")`
3. `daily_quota` → `quota_requests` → `usage_events`
4. `message_feedback` → `security_events` → `eval_reports` → `eval_scores` → `improvement_proposals`
5. 인덱스 `ix_auth_sessions_user_id`, `ix_password_reset_codes_user_id`, `ix_chat_sessions_user_id_updated_at`

`downgrade()` 처리 순서: `fk_chat_messages_faq_cache_id` 삭제 → 4 → 3 → 2(faq_cache, chat_messages, chat_sessions) → 1 의 역순으로 `op.drop_table`.

- COMMENT는 `sa.Column(..., comment="…")`, `op.create_table(..., comment="…")`로 넣는다(01과 같은 방식).
- `vector(1536)` 타입은 `pgvector.sqlalchemy.Vector(1536)`. `vector` 확장은 01의 `01-init.sh`가 `nadri` DB에 이미 만들었다(01 spec §3.1-6).
- `text[]`는 `postgresql.ARRAY(sa.Text())`, `jsonb`는 `postgresql.JSONB()`, `uuid`는 `postgresql.UUID(as_uuid=True)`.
- 빈 배열 기본값은 `server_default=sa.text("'{}'::text[]")`, 빈 객체 `sa.text("'{}'::jsonb")`, 빈 목록 `sa.text("'[]'::jsonb")`.
- CHECK 식은 허용값 튜플을 스크립트 안 상수로 복사해 `"status IN ('pending','active',...)"` 문자열로 만든다(바인드 없이 고정 문자열 — 사용자 입력 아님).

## 6. ORM (`core/models/*.py`)

- SQLAlchemy 2.x `Mapped[...]`/`mapped_column(..., comment="…")`, `__tablename__`, `__table_args__ = (제약들..., {"comment": "사용자"})`. 01의 `Base`(`nadri.core.models.Base`)를 상속.
- 클래스 이름은 §4 표의 ORM 이름 그대로. 속성 이름 = 컬럼 이름.
- 타입 매핑: `bigint`→`BigInteger`, `int`→`Integer`, `smallint`→`SmallInteger`, `numeric`→`Numeric`(Python `Decimal`), `timestamptz`→`DateTime(timezone=True)`, `date`→`Date`, `jsonb`→`JSONB`, `text[]`→`ARRAY(Text)`, `uuid`→`UUID(as_uuid=True)`, `vector(1536)`→`Vector(EMBEDDING_DIM)`.
- `server_default`는 §4와 같게 둔다(ORM만으로 테이블을 만들 일은 없지만, 테이블 생성 스크립트와 ORM이 같은지 자동 비교 테스트를 하기 위해).
- CHECK·UNIQUE·인덱스도 같은 이름으로 `__table_args__`에 둔다. CHECK 식은 모듈 상수에서 만든다:
```python
def in_check(column: str, values: tuple[str, ...]) -> str:
    """CHECK 식 문자열 "<column> IN ('a','b')" 를 만든다. 값은 코드 상수뿐이라 인용만 한다."""
```
  위치: `nadri/core/models/__init__.py`(Base 옆, 4개 모듈이 공유). 테이블 생성 스크립트는 이 함수를 import하지 않고 같은 모양의 문자열을 직접 적는다(§3-4).
- 모든 클래스에 한국어 docstring(무엇을 담는 테이블인지 + 누가 쓰는지 한 줄)([CL]).

```python
class User(Base):
    """가입한 사용자(관리자 포함). 05 인증·18 관리자 승인이 쓴다."""
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(BigInteger, Identity(), primary_key=True, comment="사용자 ID")
    username: Mapped[str] = mapped_column(Text, nullable=False, comment="아이디")
    ...
```

## 7. 테스트 DB 컨테이너 (05·06 공용 기반)

[PL] "pytest(테스트 DB 컨테이너)". 01의 테스트 방식(WSL2 Ubuntu + uv + `backend/.venv`, 서비스는 Compose)은 유지하고, **DB가 필요한 테스트만** 일회용 PostgreSQL 컨테이너를 쓴다(확인 질문 Q1).

- 도구: `testcontainers[postgres]`(dev 그룹, 버전은 구현 시점 최신으로 `uv.lock` 고정). WSL2 Ubuntu에서 `docker` 명령이 sudo 없이 되어야 한다(**미확인** — HITL H-0에서 확인).
- 이미지: compose와 같은 `pgvector/pgvector:pg18`.
- 초기화: 레포의 `infra/postgres/init/`를 컨테이너 `/docker-entrypoint-initdb.d`에 읽기 전용으로 붙이고, 테스트용 비밀번호 4개(`POSTGRES_PASSWORD=test-super`, `APP_DB_PASSWORD=test-app`, `TOOLS_DB_PASSWORD=test-tools`, `LIGHTRAG_DB_PASSWORD=test-lr`)를 넣는다 → 실제와 같은 롤 3개·DB 2개·`vector` 확장이 생긴다.
- 준비 완료 판단: init 스크립트가 끝나야 `nadri_app` 롤이 생기므로, **`nadri_app`으로 TCP 접속이 될 때까지** 0.5초 간격·최대 60초 폴링한다(testcontainers 기본 대기가 init 도중 임시 서버를 "준비됨"으로 볼 수 있음 — **미확인**).
- 그다음 환경변수 `DB_HOST=127.0.0.1`, `DB_PORT=<매핑 포트>`, `DB_USER=nadri_app`, `DB_PASSWORD=test-app`, `DB_NAME=nadri`를 넣고 `get_settings.cache_clear()` → `alembic upgrade head`(Alembic 명령 API, `backend/alembic.ini`)를 1번 실행.

## 9. 상위 문서와의 차이 (구현 판단, 아키텍처 범위 안)

| # | 내용 | 근거 |

| 1 | 한글 명칭은 [A] §5.1 표가 아니라 **ERD(`erd.py`)** 값을 쓴다. 예: `users.role` [A] "역할" → ERD "권한", `auth_sessions.id_hash` "세션 ID 해시" → "세션 키 해시", `rate_limits` "요청 제한 카운터" → "요청 제한", "…시각" → "…일시" | [A] §5.1 "다르면 ERD를 따른다", [PL] X-e |

## 11. 완료 기준 (DoD)

1. `alembic upgrade head`로 테이블 19개, `alembic downgrade 0001` → 15개 삭제·4개 유지, 다시 `upgrade head` → 19개 (테스트 DB에서 자동, 개발 DB에서 HITL 1회).
2. 19개 테이블의 테이블·컬럼 COMMENT와 타입이 ERD(`erd.py` `T`, 각주 제거 규칙)와 같다 — ORM 메타데이터와 실제 DB 둘 다.
3. ORM 메타데이터 ↔ 실제 DB(테이블 생성 스크립트 결과) 자동 비교 차이 0(§10의 무시 항목 제외).
4. §4.5 외래키 삭제 동작표가 테스트로 전부 확인된다.
5. CHECK 허용값이 ORM 상수와 같고, 허용 밖 값은 거부된다. UNIQUE 위반 시 제약 이름을 꺼낼 수 있다.
6. `nadri_tools`는 15개 테이블에 SELECT·INSERT·UPDATE·DELETE 권한이 모두 없다(01의 2개 테이블 SELECT는 그대로).
7. 단위테스트(`-m "not integration"`, Docker 필요) 전부 통과.
8. 모든 모델 클래스·함수·픽스처에 한국어 docstring, 함수 안 단계 주석([CL]).
9. 커밋은 `feat/04-db-schema`, `[Feat] …` + 작업 목록 + `Author:` 줄, AI 공동작성 표기 없음(NFR-73). `dev` 병합은 G5 승인 후. `PROGRESS.md` 작업 표 갱신.
