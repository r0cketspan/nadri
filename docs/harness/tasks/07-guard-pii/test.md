# 07-guard-pii — 테스트 설계 (test)

> spec.md와 짝. 절 번호 §n은 spec.md 기준. 작성 2026-11-21.
> 두 방향을 나눈다: ① 단위테스트(pytest, 결정적 — 모델·DB·네트워크 없음) ② HITL(사용자가 직접 확인). 이 작업은 순수 함수라 통합 테스트(`@pytest.mark.integration`)는 없다.
> 아래 표의 기대값은 spec §4 기준 정규식으로 만든 프로토타입에 전부 넣어 확인했다(2026-11-21, 멱등 포함). 구현이 정규식을 바꿔도 이 표는 그대로 통과해야 한다.

---

## ① 단위테스트 (pytest)

### 0. 공통

**파일**: `backend/tests/guard/test_pii_table.py` 하나.

**실행** (WSL2 Ubuntu, `backend/.venv`):
```bash
cd ~/code/myAgent/backend
uv run pytest tests/guard/test_pii_table.py -v
```

**작성 방식**: 표마다 모듈 수준 목록 + `@pytest.mark.parametrize`. 각 항목은 `pytest.param(입력, 기대텍스트, 기대종류, id="M-PH-01")` 처럼 **표의 ID를 그대로 `id`로** 써서 실패 시 어느 줄인지 바로 보이게 한다.

```python
MUST_MASK = [
    pytest.param("내 번호는 010-1234-5678이야", "내 번호는 010-****-****이야", ["phone"], id="M-PH-01"),
    ...
]
MUST_KEEP = [
    pytest.param("contentid 126508 상세 알려줘", id="K-ID-01"),
    ...
]

@pytest.mark.parametrize("text, expected, types", MUST_MASK)
def test_must_mask(text, expected, types): ...          # P-MASK

@pytest.mark.parametrize("text", MUST_KEEP)
def test_must_keep(text): ...                           # P-KEEP: result.text == text and result.types == []

@pytest.mark.parametrize("text, expected, types", MUST_MASK)
def test_idempotent(text, expected, types): ...         # P-IDEM
```

테스트용 번호는 전부 **지어낸 값**이다(카드는 널리 쓰이는 Luhn 시험 번호). 실제 개인정보를 테스트 파일에 넣지 않는다.

### 3. P-KEEP — 가리면 안 되는 입력 (A27)

## ② HITL — 사용자가 직접 확인

**전제**: `feat/07-guard-pii` 브랜치, 단위테스트 통과. 아래 명령은 전부 WSL2 Ubuntu 터미널에서.
**주의**: 직접 넣는 예문에는 **진짜 개인정보를 쓰지 않는다**(터미널 기록에 남는다). 번호는 지어낸 값으로.

**한 줄씩 가려 보는 명령** (H-2·H-3·H-4에서 공통으로 씀 — 한 줄 입력할 때마다 `[종류] 가린 텍스트`가 나온다, 끝낼 때 `Ctrl+D`):
```bash
cd ~/code/myAgent/backend
uv run python -c "
import sys
from nadri.guard.pii import mask_pii
for line in sys.stdin:
    r = mask_pii(line.rstrip('\n'))
    print(r.types, r.text)
"
```

### H-1. "가리면 안 되는 입력" 목록 검토 (A27, [PL §3] 07 검증)
1. 이 문서 §3 P-KEEP 표와 §4 P-KEEP-Q 표를 읽는다.
2. 각 줄에 대해 확인: "이건 개인정보가 아니니 그대로 두는 게 맞다"에 동의하는지.
3. 특히 볼 줄:
   - K-PH-02 `1588-1234`(업체 대표번호 — 안 가림, spec Q8)
   - K-AC-01 문맥 단어 없는 계좌번호 모양(안 가림 — 알려진 한계)
   - K-NM-07 영문 이름(안 가림 — 알려진 한계)
   - 반대로 P-MASK의 **M-PH-10 `064-123-4567` 관광지 대표 전화는 가린다**(spec §4.1, Q1)
4. 목록에 **빠진 관광 질문 유형**이 있으면 말한다(예: 자주 쓰는 숫자 표현). 구현자가 P-KEEP-Q에 추가하고 다시 돌린다.
- 기대 결과: 사용자가 목록에 동의하거나, 바꿀 줄을 지목. 지목된 줄은 spec §11에 질문으로 추가.

### H-2. 내 관광 질문 넣어 보기 (A27)
1. 위 명령을 띄운다.
2. 실제로 챗봇에 물어볼 법한 관광 질문을 **20개 이상** 한 줄씩 넣는다. 숫자(날짜·시간·요금·인원·주소 번지·버스 번호)가 들어간 질문을 절반 이상 섞는다.
3. 확인 포인트: 모든 줄이 `[] 입력과 같은 텍스트`로 나오는가.
- 기대 결과: 오탐 0건. `[]`가 아닌 줄이 나오면 그 문장을 구현자에게 알려 준다 → P-KEEP-Q에 추가하고 규칙을 고친다(문맥 단어 필수화·패턴 축소, [A] §12 A27 대안).

### H-3. 개인정보 변형 넣어 보기
1. 같은 명령에 지어낸 번호로 여러 모양을 넣어 본다. 예: `010 1234 5678`, `010.1234.5678`, `+82 10 1234 5678`, `제 이름은 김나리예요`, `국민은행 계좌 123456-01-234567`, `여권 M12345678`, 이메일.
2. 확인 포인트: 가려져야 할 것이 가려졌는가, 가린 모양이 알아볼 만한가(`010-****-****` 등).
- 기대 결과: 전부 가려짐. 안 가려진 모양이 있으면 알려 준다 → P-MASK에 추가 여부를 결정(규칙을 넓히면 오탐이 늘 수 있어 H-2를 다시 돌린다).

### H-4. 관광지 대표 전화 동작 확인 (spec §4.1, Q1)
1. `064-123-4567 여기 어디야?` 를 넣는다.
2. 결과 `['phone'] 064-***-**** 여기 어디야?` 를 보고, "번호로 관광지 찾기 질문은 답할 수 없다"는 동작을 받아들일지 정한다.
- 기대 결과: spec §11 Q1 답(추천안 = 가림 유지, 또는 대안 B·C).

### H-5. A29 공식 자료 확인 (구현자, 기록만)
1. 2020년 10월 주민등록번호 부여 방식 변경에 대한 행정안전부 보도자료·주민등록법 시행규칙을 찾는다.
2. 확인한 내용(성별 자리 유지 여부, 뒤 6자리 방식)과 링크를 spec §9 A29 결과 열에 적는다. 못 찾으면 "미확인".
- 기대 결과: 기록만. 규칙은 바꾸지 않는다(G3 Q3: 검증번호 미사용, 성별 자리 1~8).
